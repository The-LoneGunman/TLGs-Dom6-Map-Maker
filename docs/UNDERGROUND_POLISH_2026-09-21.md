## Implemented

- Sparse Cave, Great Cavern, Underworld, Inferno, and Abyss chambers use softer, irregular contours. Passages gain restrained curves and flared mouths where clearance permits; unrelated passages retain their separation. Styx water routes and explicit bridge crossings retain their straight geometry.
- Native D6M underground relief replaces abrupt 4/32-pixel noise blocks with smoothly interpolated, seeded elevation variation, capped at ±24 and reduced further on low terrain. Its scale follows the map dimensions, supports wrapping and extreme aspect ratios, and fades around exact native province-center heights.
- Atlas preview backdrops are subdued so playable floors stand out. These backgrounds are preview artwork, **not images embedded into the native D6M**; Dominions renders native terrain itself.
- The selector catalog is refreshed from the pinned Inspector 6.37 snapshot. No selector IDs, names or ordering changed from the bundled 6.35 catalog; source hashes and provenance now identify the current snapshot. Ordinary-site filtering recognizes both generations of bundled provenance and continues to exclude explicitly non-random custom sites.
- Optional population-matched initial defenders use the released v3 profiles described above. Explicit patch and era declarations are required; unsupported contexts retain native armies. Historical v1/v2 revisions remain unchanged until explicitly upgraded.
- Start-neighbor validation now includes every endpoint in a gateway group, including same-plane and cross-plane links. Existing guardians are preserved in the editor, but unsafe authored guardians, thrones or special-unit directives in those protected neighbors block playable export.

This intentionally changes affected underground silhouettes and height rasters, including when reopening an existing project. It is not a promise that their previous rendered pixels remain identical.

## Population-aligned initial defenders: implemented, data-gated

The [official map manual](https://www.illwinter.com/dom6/dom6mapman.pdf) distinguishes `#poptype` recruitment from the initial independent army: assigning a population type does not replace that army. The user approved an opt-in mode to align ordinary initial defenders with assigned recruitment populations, while preserving custom guardians and protected starts/direct neighbours.

The opt-in policy, read-only resolver, export integration, coverage panel, and selected-province army/status readout are implemented on this branch. Current-map population edits re-evaluate coverage without regeneration. Templates are revision-pinned and require an exact declared patch/mod context, any evidence-required era, matching catalog identities, and supported terrain. Patch and era are not filled in automatically. Custom guardians always take priority; protected starts/neighbours (including all gateway endpoints), locks, owned or blocked provinces, thrones, and raw directives prevent unsafe automatic additions. Unsupported provinces retain native armies instead of becoming undefended.

The current registry revision, **`dom6-6.37-native-2026-09-21-v3`**, contains 76 profiles with the [documented scope and exclusions](research/NATIVE_POPULATION_DEFENDERS_2026-09-21.md). Activation remains off by default. The earlier **v2** still contains only **Pale Ones #81**, with **one Pale One Commander #1463 and 15 Pale Ones #1465**, for **unmodded 6.37, Middle Age, dry Cave terrain**; the previously exposed empty v1 stays empty. Saved maps must explicitly adopt v3, so an update cannot silently add or replace armies.

Populations **43, 44, 72, 88, 105 and 106**, plus unsupported terrain/era/patch/mod contexts, retain native armies. The separately verified [82-row recruitment table](research/POPULATION_RECRUITMENT_TABLE_2026-09-21.md) establishes static default membership, not automatic defender acceptance or all runtime recruiting behavior. Unit names alone, old-game defender lists, and national recruitment tables remain insufficient membership evidence. Templates use explicit fixed counts, not the game's independent-strength formula, and do not replace replenishing post-capture PD rules. README and User Guide explain the supported scope, declarations, coverage display and revision upgrade.

### Maintainer roster-verification checklist

1. Record the exact game patch, era, enabled mods/load order, population ID, and tested land/water/cave conditions. Exclude national and magic-site recruitment additions from the population observation.
2. Establish commander and troop membership from a controlled native fixture or a separately verified, versioned membership table. Use pinned data for routine numeric IDs, exact names and traits; reserve native ID-panel checks for ambiguous identity or cross-checking. A matching selector name alone is not proof of population membership.
3. Check commander leadership/capacity and every unit's survival in each allowed medium; test the proposed initial army rather than assuming recruitability makes a safe defender group.
4. Record the chosen fixed squad counts separately from roster facts. Do not claim vanilla independent-strength equivalence, calibrated combat balance, or verified persistent PD.
5. Keep reproducible source/evidence references, patch/mod scope, catalog identity/provenance, and an immutable profile revision. Require independent review and focused resolver/export/native checks before adding a profile; leave unresolved populations unsupported.
